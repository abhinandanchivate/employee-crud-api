How Docker images are structured as layered filesystems

📐 Layer Characteristics

  • Each Dockerfile instruction creates a new layer
  • Layers are immutable once created
  • Layers are content-addressable (identified by SHA256 hash)
  • Shared layers are stored only once on disk
  • Order of layers matters for cache efficiency

⚡ Layer Optimization Tips

  • Combine RUN commands to reduce layer count
  • Place frequently changing instructions last
  • Use .dockerignore to exclude unnecessary files
  • Clean up in the same layer (rm -rf /var/cache/*)
  • Use multi-stage builds for smaller final images

🔍 Inspect Layers

# View image layers
docker history myimage:latest

# Detailed layer info
docker inspect myimage:latest

Internal Architecture

The core mechanisms that power Docker images

📋

Image Manifest

JSON document that describes the image, including layer digests, configuration, and platform info.

{
  "schemaVersion": 2,
  "mediaType": "...manifest.v2",
  "config": { "digest": "sha256:..." },
  "layers": [ ... ]
}
🔐

Content Digest (SHA256)

Unique cryptographic hash identifying each layer and image. Ensures integrity and enables deduplication.

sha256:a3ed95caeb02...

# Immutable reference
docker pull nginx@sha256:abc123...
🗂️

Union Filesystem

Merges multiple read-only layers into a single coherent filesystem view. OverlayFS is the default driver.

# OverlayFS layers:
upperdir/ # container writes
lowerdir/ # image layers
merged/   # unified view
🐄

Copy-on-Write (CoW)

Files are copied to the writable layer only when modified. Original layers remain untouched.

# Read: from lower layer
# Write: copy up, then modify
# Delete: whiteout file created
💾

Storage Driver

Manages how layers are stored and combined. Common drivers: overlay2, devicemapper, btrfs, zfs.

# Check storage driver
docker info | grep "Storage Driver"

# Layer location
/var/lib/docker/overlay2/
⚡

Build Cache

Reuses existing layers when instructions and context haven't changed. Dramatically speeds up builds.

# Cache hit
---> Using cache abc123

# Skip cache
docker build --no-cache .

Image Commands Reference

Essential commands for managing Docker images

docker build -t name:tag .
Build image from Dockerfile in current directory
docker images
List all local images with sizes
docker history image
Show layer history and sizes
docker inspect image
View detailed image metadata as JSON
docker tag source target
Create a new tag for an image
docker push repo/image:tag
Upload image to a registry
docker pull repo/image:tag
Download image from a registry
docker save image > file.tar
Export image to a tar archive
docker load < file.tar
Import image from tar archive
docker rmi image
Remove an image (and unused layers)
docker image prune -a
Remove all unused images
docker system df
Show Docker disk usage breakdown
