Docker Complete Workflow

Dockerfile → Image → Container

📄

Dockerfile BLUEPRINT

A text file containing instructions to build a Docker image. It defines the base image, dependencies, configuration, and commands.

# Example Dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]
docker build
📦

Docker Image TEMPLATE

A read-only template with layered filesystem. Images are portable, versioned, and can be shared via Docker Hub or private registries.

# Build an image
docker build -t myapp:v1 .

# List images
docker images

# Push to registry
docker push myapp:v1
docker run
🚀

Container INSTANCE

A running instance of an image. Containers are isolated, lightweight, and ephemeral. Multiple containers can run from the same image.

# Run a container
docker run -d -p 3000:3000 myapp:v1

# List running containers
docker ps

# Stop container
docker stop container_id

Key Concepts

📄 Dockerfile Instructions

  • FROM — Sets the base image (e.g., ubuntu, node, python)
  • WORKDIR — Sets the working directory inside container
  • COPY/ADD — Copies files from host to container
  • RUN — Executes commands during build (install packages)
  • ENV — Sets environment variables
  • EXPOSE — Documents which ports the container listens on
  • CMD/ENTRYPOINT — Specifies the default command to run

📦 Image Layers

  • Each instruction in Dockerfile creates a new layer
  • Layers are cached for faster subsequent builds
  • Images are read-only; containers add a writable layer on top
  • Shared layers between images save disk space
  • Use multi-stage builds to reduce final image size
  • Tag images with versions (e.g., myapp:v1.0.0)

🚀 Container Features

  • Isolated process space, network, and filesystem
  • Shares the host OS kernel (lightweight vs VMs)
  • Can be started, stopped, restarted, and removed
  • Volumes persist data beyond container lifecycle
  • Networks enable container-to-container communication
  • Resource limits (CPU, memory) can be configured

🔄 Docker Registry

  • Docker Hub — public registry for sharing images
  • Private registries for internal/enterprise use
  • docker pull downloads images from registry
  • docker push uploads images to registry
  • Images identified by name:tag (e.g., nginx:latest)
  • Official images are verified and maintained

Essential Commands

docker build -t name:tag .
Build image from Dockerfile in current directory
docker run -d -p 8080:80 image
Run container detached with port mapping
docker ps -a
List all containers (running and stopped)
docker images
List all local images
docker exec -it container bash
Open interactive shell in running container
docker logs container
View container logs
docker stop container
Stop a running container gracefully
docker rm container
Remove a stopped container
docker rmi image
Remove an image from local storage
docker-compose up -d
Start multi-container app from compose file
